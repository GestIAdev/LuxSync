Two structural changes to defeat half-time lock during Melodic Techno

== Proposal B: TRUTH TELLER — expose true pre-Kalman Oracle BPM ==

The legacy `rawBpm` field was a lie: after "KILL THE POCKETS" it became
an alias for the Kalman-smoothed value, identical to `musicalBpm`. The
actual raw Oracle output (this.tempoOracle.bpm) was consumed by
kalmanUpdate() and never exposed, blinding us to hard octave jumps
that the Kalman was masking as gradual drift.

New fields threaded through the full chain:
  RhythmTracker.oracleRawBpm    = this.tempoOracle.bpm (pre-Kalman)
  RhythmTracker.oraclePeakHeight = this.tempoOracle.peakHeight (raw NSDF)
  -> BPMOutput -> SensesPipeline -> AnalysisResponseBuilder
  -> WorkerProtocol -> AudioPipelineManager -> TrinityBrain -> TickEngine

Logger format upgraded:
  BEFORE: BPM=63.64 (raw=63.66) conf=0.86
  AFTER:  BPM=63.64 (oracle=63.10) (kalman=63.64) conf=0.86 peak=0.670

Now we can see if the Oracle is jumping hard (oracle=63.10) while the
Kalman drifts slowly (kalman=63.64), or if both move together. The
`peak` field shows the raw NSDF peak height for confidence auditing.

== Proposal A: ASYMMETRIC OCTAVE SHIELD ==

The symmetric hysteresis gate (60f @ conf>0.7 for ALL >8% jumps) was
failing on the #1 DSP failure mode: octave-down (÷2) during breakdowns.
The anyma2misterio.md log proved the shield accepted 85→63 BPM after
60 frames because conf=0.86 > 0.7 — the half-time periodicity is
genuinely strong during breakdowns.

New asymmetric thresholds in TickEngine hysteresis gate:
  ÷2 (OCT_DOWN): 180 frames (~8.4s) @ conf>0.9  — extreme defense
  ×2 (OCT_UP):    20 frames (~0.9s) @ conf>0.6  — fast recovery
  other >8%:      60 frames (~2.8s) @ conf>0.7  — default (unchanged)

Design rationale:
  - A breakdown lasting <8.4s cannot force the octave-down. Anyma
    breakdowns are 16-32s, so the shield will eventually yield — but
    by then the breakdown IS the dominant signal and lights SHOULD
    follow it.
  - When the kick returns, the Oracle jumps back to τ (×2 path). The
    20-frame / conf>0.6 threshold accepts this in ~0.9s — fast
    recovery from a previous half-time lock.
  - FREEWHEEL is unaffected: the shield only acts when workerBpm>0
    && conf>0.5. During freewheel (worker deaf), the entire hysteresis
    block is skipped.

Shield tags in logger:
  ⚠️OCT-DOWN🛡️ = ÷2 rejected/holding (breakdown defense active)
  ⚠️OCT-DOWN✅ = ÷2 confirmed after 180f @ conf>0.9 (rare)
  ⚠️OCT-UP🛡️   = ×2 pending fast confirmation
  ⚠️OCT-UP✅    = ×2 accepted (kick returned, recovery)
  🛡️ACCEPT/HOLD/REJECT = non-octave large jumps (unchanged behavior)
