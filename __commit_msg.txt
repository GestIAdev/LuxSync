WAVE 7632: Fix Amnesia Bug — last-active-show pointer file

The diagnostic logs revealed the true root cause:

  Save writes to: 6testNUEVO.v2.luxshow ✓
  loadActive loads from: current-show.v2.luxshow ✗ (DIFFERENT FILE!)

The user opened a named show file (6testNUEVO.v2.luxshow), edited
positions, and saved. The save correctly wrote to the named file.
But on app restart, loadActive() always loads current-show.v2.luxshow
(the default active show), which has the OLD positions. There was no
mechanism to track which named show was last active.

Fix: Added a last-active-show.json pointer file in the shows directory.

1. StagePersistence.getActiveShowPath() — now checks the pointer file
   first. If it exists and points to a valid file, returns that path.
   Otherwise falls back to current-show.v2.luxshow.

2. StagePersistence.saveShow() — after saving, writes the target path
   to the pointer file. So the next loadActive() picks up the right
   file.

3. StagePersistence.loadShow() — after loading, writes the loaded path
   to the pointer file.

4. StageIPCHandlers load/loadActive — now send the actual filePath in
   the lux:stage:loaded event. Without this, the frontend defaults
   showFilePath to 'active', causing saves to go to the wrong file.

Also removed the WAVE 7631-DIAG diagnostic logs (culprit found).
