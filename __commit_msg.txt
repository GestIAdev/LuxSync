WAVE 7624: Defeat the final bosses — IK flip + ceiling spike

Bug 1: IK Auto-Flip (Teleportation Ghost)
- Root cause: solveInto's resolveShortestPanPath uses currentPanDMX to
  choose between Solution A (normal) and Solution B (flipped ±360°).
  The resolver fed node.currentPosition.pan (the OFFSET-POLLUTED value)
  as currentPanDMX. When the L0 pan_offset pushed the physical head
  past the midpoint, the next tick's solver saw the flipped solution as
  mathematically closer and triggered a 180° jump.
- Fix: Added _ikPurePanMemory Map<NodeId, number> in NodeResolver. After
  solveInto, the PURE IK pan (before any offset) is saved. On the next
  tick, this pure value is passed as currentPanDMX instead of the
  polluted currentPosition.pan. The solver's flip heuristic now only
  remembers the pure 3D target trajectory, not the orbital offset.
  currentPosition.pan still receives the offset-polluted safePan for
  the UI/RELEASE engine — only the solver's memory is isolated.

Bug 2: Ceiling Spike on Pattern Switch
- Root cause: setManualKinetics resets _phaseMap to 0 on every pattern
  change. The pattern function at phase=0 produces its initial position,
  causing a full-amplitude offset in a single frame (up to ~64 DMX steps
  for tilt). For ceiling fixtures with tilt inversion, this spikes to
  the ceiling.
- Fix: Added _offsetFadeIn Map<NodeId, number> in AetherKineticEngine.
  Reset to 0 on every setManualKinetics call. In tick(), ramps from 0
  to 1 over ~1 second (using real dtSeconds). Multiplied into the
  pan_offset/tilt_offset output in IK mode only, smoothly blending the
  new pattern's offsets from zero to full amplitude. Classic mode base
  computation is unaffected.

Both fixes are zero-alloc (pre-allocated Maps) and preserve the WAVE
7621 offset-fusion architecture.
