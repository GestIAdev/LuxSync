WAVE 7613: Spatial Radar Programmer Route — wire UI to programmerStore

Following the WAVE 7612 forensic audit, the applySpatialTarget engine route
was found broken: the arbiter stored target_x (snake_case) in
_motorKineticOverrides but never propagated it to the result record, so
NodeResolver never saw targetX (camelCase) and the IK path was never taken.

This commit implements Option B from the forensic report: wire the
SpatialTargetPad directly to programmerStore.setSpatialPosition(), which
writes targetX/Y/Z (camelCase) to fixtureOverrides. ProgrammerAetherBridge
extracts these at 44Hz and injects them into NodeArbiter._manualOverrides
as targetX (camelCase), which NodeResolver reads via CH_TARGET_X to
trigger the IK solve path.

Changes:
- KinRadarViewport.tsx: handleTargetChange now calls both
  movementStore.setSpatialTarget(t) [for UI/fan] AND
  programmerStore.setSpatialPosition(t) [for IK engine]
- KineticsCathedral.tsx: handleViewMode clears programmerStore
  spatial targets when leaving SPATIAL mode, preventing ProgrammerAetherBridge
  from injecting stale targets after switching to classic radar

Pipeline (repaired):
  SpatialTargetPad drag
    -> movementStore.setSpatialTarget()     [UI crosshair + fan sub-targets]
    -> programmerStore.setSpatialPosition() [targetX/Y/Z to fixtureOverrides]
    -> ProgrammerAetherBridge.extractKinetic() at 44Hz
    -> ch['targetX'] = ov.targetX           [camelCase, matches CH_TARGET_X]
    -> IPC: lux:aether:setManualOverrides
    -> arbiter.setManualOverride(nodeId, { targetX, targetY, targetZ })
    -> arbiter.arbitrate() -> record['targetX'] = manual['targetX']
    -> NodeResolver: channelValues['targetX'] !== undefined -> IK PATH
    -> solveInto() -> DMX pan/tilt -> moving head moves
