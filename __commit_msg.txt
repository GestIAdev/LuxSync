WAVE 7622: Spatial gate — prevent setManualPattern from sabotaging IK

When a manual pattern (sweep, circle, etc.) was activated from the UI,
setManualPattern forcefully injected pan_base/tilt_base into
_manualOverrides, even when a spatial target was actively commanding
the fixtures via _motorKineticOverrides. This dropped the fixtures
out of IK mode and forced them to a flat 0.5/0.5 anchor.

Root cause: The anchor resolution loop (lines 730-796) checked
motor['pan_base']/motor['tilt_base'] for the IK anchor, but after
WAVE 7621 Phase 3, the motor override in IK mode contains
targetX/Y/Z + pan_offset/tilt_offset, NOT pan_base/tilt_base. So
ikPan/ikTilt were null, and the code fell back to 0.5, writing
pan_base=0.5/tilt_base=0.5 to _manualOverrides — sabotaging the IK.

Fix: Added a spatial gate at the top of the per-node anchor loop.
If motor['targetX'] !== undefined (spatial target active), skip the
anchor injection entirely (continue). The L2 engine emits
pan_offset/tilt_offset in IK mode (WAVE 7621 Phase 3), and the IK
solver handles the center. Only the classic mode path (no spatial
target) proceeds with the anchor resolution and pan_base/tilt_base
injection as before.
