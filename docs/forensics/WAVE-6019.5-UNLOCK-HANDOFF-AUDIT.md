# WAVE-6019.5 — FORENSIC AUDIT: Unlock Handoff & Post-Cleanup Math Corruption

**Date:** 2025-01-21
**Auditor:** Cascade Core Forensic Engine
**Scope:** L2→L0 handoff (Unlock button), React UI residual state, and mathematical corruption for fixtures near X=0 during manual override clearing.

---

## EXECUTIVE SUMMARY

**TARGET 1 — Sabotage of the Handoff:**
**CORREGIDO 2025-01-21.** El mapeo `'none' → 'hold'` en `KineticsBridge.ts:74-76` era una **trampa lógica arquitectónica**, no un diseño inofensivo. Al traducir Unlock como `'hold'`, el backend ejecutaba Fix C (migración motor→manual), lo que **secuestraba permanentemente la capa L2** con la coordenada espacial del momento del unlock. Esto inmortalizaba cualquier glitch espacial activo (ej. focos X=0 apuntando al techo) y enmascaraba el motor automático L0.

**Fix aplicado:** `'none'` ahora mapea a `'release'` (purga destructiva pura). `'hold'` queda reservado exclusivamente para freeze intencional del operador. El backend separa ambas rutas: `'release'`/`'idle'`/`null` → purga sin rescate; `'hold'`/`'static'` → Fix C preservado.

**TARGET 2 — Mathematical Corruption (X≈0):**
No `NaN`, `Math.atan2` singularity, or division-by-zero was found in the unlock/cleanup hot path (`NodeArbiter._applyRelativeOffsetFusion`). The observed "ceiling pointing" and "desynchronization" are root-caused by **missing/undefined orientation metadata** (Fix A/B) and **erroneous left/right phase classification** for central fixtures (Fix D), not by arithmetic corruption on X=0.

## TARGET 2: MATHEMATICAL CORRUPTION POST-CLEANUP (X≈0)

### 2.1 NodeArbiter._applyRelativeOffsetFusion

**Lines:** `NodeArbiter.ts:758-922`

```typescript
@/electron-app/src/core/aether/NodeArbiter.ts:758-922
private _applyRelativeOffsetFusion(): void {
  const amp = this._relativeOffsetAmplitude
  const ampPan  = amp * RELATIVE_OFFSET_SCALE_PAN   // 0.5
  const ampTilt = amp * RELATIVE_OFFSET_SCALE_TILT   // 0.5
  // ...
  for (const [nodeId, record] of this._result) {
    // ...
    const basePan  = hasMotorPan  ? (motorPan  as number)
                   : hasManualPan ? (manualPan as number)
                   : 0.5
    const baseTilt = hasMotorTilt  ? (motorTilt  as number)
                   : hasManualTilt ? (manualTilt as number)
                   : 0.5
    // ...
    let final = basePan + ox * ampPan * distScale * gimbalFactor
    if (final < 0) final = 0
    else if (final > 1) final = 1
    record['pan'] = final
    // ...
    let finalTilt = baseTilt + oy * ampTilt * distScale
    if (finalTilt < TILT_ARBITER_MIN) finalTilt = TILT_ARBITER_MIN  // 0.15
    else if (finalTilt > TILT_ARBITER_MAX) finalTilt = TILT_ARBITER_MAX  // 0.85
    record['tilt'] = finalTilt
  }
}
```

**AUDIT RESULT:**
- **No `Math.atan2`.**
- **No division by X, delta, or any physical coordinate.**
- **No `NaN` generation path.** All inputs are guarded by `isFiniteChannelValue()`.
- **Fallbacks are safe:** `0.5` (center) for missing base, `0` for missing offset.
- **Clamp boundaries are hard:** `TILT_ARBITER_MIN = 0.15` (~38 DMX), `TILT_ARBITER_MAX = 0.85` (~217 DMX).

The Arbiter's fusion math is **arithmetically bulletproof**. The "ceiling pointing" symptom does **not** originate here.

### 2.4 The Real Culprit — KineticAdapter.ts (Pre-Fix D)

```typescript
@/electron-app/src/core/aether/adapters/KineticAdapter.ts:238-257
// WAVE 6019.4 FIX — ZONA NEUTRAL (EPSILON):
const posX = node.physicalPosition?.x ?? node.position?.x
let lrPhaseOffset = 0
if (posX !== undefined && Number.isFinite(posX)) {
  if (posX > 0.5) {
    lrPhaseOffset = Math.PI
  }
  // |x| ≤ 0.5 → 0 (zona neutral)
} else {
  lrPhaseOffset = (node.zoneId && ... && node.zoneId.includes('right')) ? Math.PI : 0
}
```

**PRE-FIX D BEHAVIOR (Bug 1A):**
- Before Fix D, the code relied solely on `node.zoneId.includes('right')`.
- A fixture at `x = 0.1` (slightly right of center) but in a zone named `"center-left"` would get `phase = 0`.
- A fixture at `x = 0.1` in a zone named `"center-right"` would get `phase = π`.
- This caused **symmetric desynchronization** for fixtures near X=0.

**POST-FIX D:**
- Physical position `posX` is checked first.
- Neutral zone `|x| ≤ 0.5` forces `phase = 0`, keeping central fixtures synchronized.

### 2.5 The Real Culprit — VibeMovementManager.ts (Pre-Fix B)

```typescript
@/electron-app/src/engine/movement/VibeMovementManager.ts:1053-1062
const mountOrientation = node.ikOrientation?.installation ?? 'floor'
```

**PRE-FIX B BEHAVIOR:**
- `node.ikOrientation` was always `undefined` in production (because `NodeExtractionPipeline` never hydrated it — see Fix A).
- `mountOrientation` became `undefined`.
- `generateIntent` applied **floor clamps** (`Math.min(y, +0.15)`) and **floor tilt offsets** (`-0.35`).
- Meanwhile, `NodeResolver._shouldInvertClassicKineticAxes` detected ceiling mount from `deviceOrientation` and applied `255 - dmxValue`.
- The combination of **floor-oriented VMM math + ceiling-oriented resolver inversion** pushed the beam to the ceiling.

**POST-FIX B:**
- Fallback to `'floor'` with lowercase normalization.
- Ceiling mounts get mirrored clamp (`Math.max(y, -0.15)`) and `tiltOffset = 0`.
